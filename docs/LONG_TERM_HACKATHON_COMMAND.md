# 장기 해커톤 통합 총괄 운영 헌장

> 최초 등록 2026-10-24 KST · 사용자 확정 정책 · 저장소: `hibi89/hackathon-command-center-2026@main`
> **적용 범위:** 2026년 KIC·PayPal·UGREEN을 시작으로 **이후 사용자가 선택·참가하는 모든 해커톤**. 이 저장소는 연도별로 폐기하지 않는 통합 기록부다.

## 최상위 목표
- **시간 제한 없는 장기 참가:** 3~5년, 10년 이상 걸리더라도 공식 출품을 누적한다. 50건/100건은 장기 지향점이지 기한·당락·참가 의무가 아니다.
- **입증 가능한 누적 경력:** 참가 등록 → 공식 작품 제출 → 재현 가능한 코드·데모 → 본선/공식 수상 → 상용 고도화 → 실제 유료 납품을 별개 상태로 기록한다. 성과를 과장하거나 본선을 수상으로 표시하지 않는다.
- **사업 자산화:** 해커톤별로 재사용 가능한 공통 기술, 대상 고객, 크몽 상품 후보, 상업화 권리/라이선스, 데모 검증, 실제 판매/후기/유지관리 여부를 평가한다. 1대회=1판매상품 의무는 없다.
- **프리랜서 생존 우선:** 이미 계약된 유료 납품·고객 장애 대응·기본 생계 수입을 해커톤 추가 참가보다 우선하고, 필요 시 다른 소득원을 병행할 수 있게 일정에 여유를 둔다. 수상은 통제할 수 없는 변수이므로 생계 계획에서 확정 수입으로 잡지 않는다.

## 통합 지휘권 및 신규 대회 진입 절차
1. **상위 총괄 = 이 저장소 `main`의 영구적인 포트폴리오/신규 대회 탐색/신청 위험/전체 일정·비용 감독 역할.** 단기적으로 관리 대회가 3개라는 말은 역사적 스냅샷일 뿐 총괄의 범위 제한이 아니다.
2. 기존 실행 구조는 **현행 4개 채팅**(상위 총괄 1 + KIC·PayPal·UGREEN 총괄 겸 개발 3) 유지. 신규 해커톤에 실제 참가하기로 결정하면 사용자가 허가한 후 그 대회의 담당 총괄·직접 개발 역할 및 저장소/브랜치·부트스트랩을 추가한다. 임의 채팅 증설·레포 생성·대회 등록을 하지 않는다.
3. 신규 후보는 먼저 [2027 참가 후보·확정 일정](2027_HACKATHON_WATCHLIST.md)에 넣고 `data/future_hackathons.json`에 구조화한다. 공식 URL·모집 상태·시작/마감·KST 환산·한국 거주자/개인/온라인/비용/사용 규정·상품화를 확인한다.
4. 참가 의사 결정 후에만 후보 → 승인 → 등록 → 제출작 개발 → 공식 제출 → 평가/수상 → 상용화 후보 → 고객납품의 상태를 바꾼다. 각 단계의 주최 증빙·링크/커밋/영수증을 남긴다.
5. 출품 규정상 사전 제작·동일 작품 중복 제출·AI 사용·오픈소스·상업적 재사용을 제한할 수 있다. 기존 코드는 대회 규정을 검증한 후에만 재활용한다. 고객/팀/주최측 소유 자료는 권리 확인 없이 상품화하지 않는다.
6. 해커톤 사이에는 공용 템플릿·테스트·배포·견적·데모를 재사용하되, 새 대회에서 인정되는 신규 기여와 과거 코드 재사용을 명확히 구분한다.

## 비용·보상·재투자 원칙 (목표 ≠ 승인된 지출)
- **현재 3개 대회 신규 현금지출 목표는 각각 0원이며 그대로 유지.** 미래 대회도 참가비, 유료 계정, API, 장비/출장비를 사전 심사한다.
- 사용자는 **공식 입상·수상 실적이 생기면 개인적 보상으로 월 미화 100달러 이상 수준의 고급 AI 구독을 검토**하고, **상금이 실제 지급되어 축적되면 성능 높은 노트북 구입을 검토**하는 장기 보상 구상을 밝혔다. 이는 희망/조건부 검토이며 구독 개시·구매·예산 증액 승인이 아니다.
- 실제 상금은 원천징수·세금·통화·수령 제한/지급 지연을 확인한 다음에만 가용 자금으로 인정한다. 수상 발표와 상금 입금은 별개. 단일 수상에 생계 예산을 의존하지 않는다.
- 유료 결제·재정 약정·새 구독 등은 **그 시점에 별도 사용자 명시 승인** 후 진행. Public GitHub에 개인 재산·잔액·계좌·세금/증빙·민감정보는 남기지 않는다.

## 전체 총괄 운영 주기 (자동 수행 아님)
- 사용자가 대회 탐색/일정 확인을 요청하면 공식 페이지 위주로 후보를 재검증하고 이 저장소의 목록·KST 마감·추적 상태를 갱신한다.
- 새 대회를 참가하기 전에는 기존 유료 납품 및 활성 해커톤 일정과 충돌하는지 확인하고, 개발 가능 시간·예비시간·마감 완충을 검토한다.
- 주요 작업 후 새 공식 마감·등록 증거·원격 SHA/CI·데모·상품화 전환/납품 실적을 업데이트한다. 별도 자동화 요청과 설정이 없는 한 백그라운드 모니터링·예약 작업은 없다.
- 공개 저장소에는 공개 가능한 일정·규정·운영 원칙만 기록한다. 실제 사용자 로그인·지급 정보·고객 자료는 기록 금지.
