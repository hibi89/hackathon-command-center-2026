## 출고 실행 순서

### 배치 1 — 가장 빠른 판매 검증 3종
1. DATA2WEB Studio → PREP → FlowPilot Universal 순서로 **각각 독립 SKU** 구축(가정상 기술95면 기능 재작성 금지); 상품마다 최종설계 추적표, 기존 테스트, Windows/실 브라우저 고객형 smoke, 사용법·샘플·오프라인 설치/ZIP 무결성, 라이선스/NOTICE/취소·지원 정책 검수.
2. 공통 납품 형태: 사용자가 직접 실행하는 단일 Windows ZIP/installer 또는 적합한 로컬 웹 실행기 + 샘플 입력/예시 출력 + PDF/HTML 매뉴얼 + 2~3분 데모 + 명시적 제한사항 + 불변성/복구 확인 + 버전/SHA. 고객의 개인정보를 무승인으로 외부 AI/API에 보내지 않음.
3. 구매자 테스트와 운영/지원 비용을 측정하여 다음 배치 순서 변경. *크몽 등록/게시/판매·고객 외부 연결은 별도 사용자 승인 단계*.

### 배치 2 — 독립 실행형·개발/데이터 작업형
4~12위에 동일 수용 게이트 적용. 각 고객 환경에서 재현성·오탐/오답률·외부 컴포넌트 라이선스를 개별 승인. **원본 기능은 보존**하고 UI 개편을 이유로 기능을 축소하지 않는다.

### 배치 3 — 복합·엔터프라이즈·규제/위험 상품
13~29위는 통합/API/IAM/실고객/규제/재배포권 검증이 출시 병목. 상위 배치의 판매/지원 실증 없이 29개를 동시에 게시하거나 자체 범용 AX 플랫폼을 먼저 구축하지 않는다. 안정된 SKU로 재사용 가능한 공통 요소(패키지 검증, 로그/버전/샘플, 설치·지원 문서)만 추출한다. 공통화 때문에 기능·보안경계를 결합하거나 제품별 블루프린트를 훼손하지 않는다.
