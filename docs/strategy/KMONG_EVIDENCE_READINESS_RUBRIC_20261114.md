> 2026-11-14 KST. **사용자 요청 '29개 점수를 매겨라'에 따른 보수적 중간 평가**. 이 점수는 `최종설계 전체 공식 완성률`이 아니라, **제품화 검증을 뒷받침하는 GitHub 증거 준비도**이다. 기존 `official_final_completion`, 작업자 내부 진척률·상품 등록/작업중/RELEASE HOLD는 절대 덮어쓰지 않는다. 수치 미산정 반복을 피하면서 제품별 부족한 증거를 정량화하는 용도이다.

## 왜 두 종류 이상의 수치가 필요한가

- **작업자 보고율:** 최종설계 전체 공식 인증이 아니라 담당자가 과거 개발 범위에 대해 공지한 85/95 등; 2026-11-13 역사 기록과 신규 최신 작업 이력은 별개.
- **검증증거 확보점수:** 이번에 도입한 29종 동일 100점 기준. 소스·설계와 SHA 고정 CI/패키징/부정 테스트/고객·권리 인수 증거의 **존재 및 확인 수준**을 기계적으로 측정. 높은 점수도 기능 완성률·실구매자 품질·실제 상품 100%를 의미하지 않음.
- **제품별 승인 최종설계 공식 완성률:** 각 REQ 전체 승인 가중치 100점에 대해 실제 확인된 항목 합. 현재 DATA2WEB만 기 승인 점수72/100, 나머지 정식 전체항목 승인/재실행 전 미산정. 고정 rubric 일반점수로 대체 불가.
- **상용 출시/크몽 등록 여부:** 권리·실고객·가격/환불/지원·소유자 승인·실게시 URL 실증은 별도.

## 부정/혼동 방지

- `A01` 수집기 신규 branch P95 추가10검증은 전체 Windows feature CI가 아직 검증되지 않았으므로 **과거 main CI**를 참조한다. branch SHA와 다른 과거 실행이라는 위험 표시.
- `HAE`/AZENTFLOW P85 지정 Actions는 일부 테스트가 PASS지만 전체 2개 실패로 결론 FAILURE이다. 자동 20점 CI 가산 **금지**.
- `CANDIDATE-04 Factory AX`는 W1 VERIFY 85까지 개발돼도 **W2~W4 전체 Factory AX 상용 완성률 85%가 아님**.
- `CANDIDATE-11 FlowPilot Universal`의 해커톤 UGREEN 스킬과 범용 Windows SMB/NFS 판매용 앱을 혼합하지 않는다. 중앙 링크는 UGREEN 해커톤 브랜치지만 범용 상품 구현 소스 별도 미확인, 해당 공통 점수는 매우 낮게 나온다.
- `CANDIDATE-12 WORKNOVA Desk`는 중앙 제품 인덱스가 PayPal 해커톤 `lead/paypal`을 가리킨 이전 흔적이 있다. 실 제품은 `Freelancer@product/worknova-desk-local`이며 해당 코드·CI를 별도로 score manifest에 연결한다. **원래 인덱스는 무단 수정하지 않고 링크 불일치를 위험사항으로 출력**.
- `CANDIDATE-05/07/08/09` 등 설계 repo와 실제 엔진 repo가 분리된 상품은 **각 실제 제품 source branch의 CI를 참조**한다. 모의 DBVORA/실고객 미검증, 이름 비슷한 다른 상품의 SUCCESS를 본 제품 GO로 전파하지 않는다.
- 권리·서명·고객 환경·크몽 게시·모든 요구사항 100점 중 한 항목이라도 증거 부족이면 **상품 최종100 또는 출시 승인을 절대 자동 선언하지 않는다**. 점수10/100은 기획 10%가 아니라 허브 링크 증거10점일 뿐.

## 사후 추적/인수 기준

- `source`·`blueprint`·`ci`는 수집자가 사전 확인한 **명시 29건 allowlist**이므로 새 제품·브랜치/CI 증거 확인 전 자동 추가 금지. 현재 35 App 저장소 범위·80 refs·29 원장 제품·19 상품서비스 및 기존 데이터 보존.
- CI는 전체 워크플로가 **SUCCESS**여야 하며, 한 Job만 PASS인 FAILURE를 성공 취급하지 않는다. 정확 코드 SHA, Job 이름/플랫폼, 새 소스 HEAD와 차이 경고를 같이 보관한다. `status=NO_RUN`은 검증기 실행이 없다는 뜻이지 개발 없다는 뜻이 아니다.
- 작업자 보고율 최신 자동수집은 별도 개선 단계로 남으며 현재 16개 과거 수치만 존재. 추가 12개 후보의 P85/P95 목표 달성과 공식 완성을 혼동하지 않는다.
- 정상 실행: `python3 -B -m unittest discover -s tools/kmong_hub_sync -p 'test_*.py' -v` → GitHub App 실제 `workflow_dispatch`/정상 예약 → snapshot 29종 수치 모두 존재·20개/40개 등 정확 항목 감사 → 동일 데이터 NO_CHANGE → 원본 공식 score+등록 이력 불변.
- 실제 GitHub Actions 실 run이 완료되기 전 **코드 커밋만으로 운영 완료 주장 금지**, 그 상태는 `검증 대기`로 기록.
