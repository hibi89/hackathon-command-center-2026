# 크몽 29종 공통: 최종설계 고정 + Sol Ultra 독립 검수·UX 고도화 프로토콜

**확정 정책 2026-11-13 KST:** 해총(GPT-6 고추론)이 최종설계·기능 구현·통합/출고 최종 판정 책임을 유지한다. Codex Sol Ultra(사용자 지칭)는 **기존 GitHub 최종설계의 충실도 감사, 결함/보안 점검, UI/UX 품질 개선, 회귀 테스트 강화**에 집중한다. 모든 제품 코드를 Sol Ultra로 통째로 **새로 생성/재작성하지 않는다.** 제품별 50→70→85→95→100 단계 기준은 변경하지 않으며, 설계 대비 기술 완성률과 실제 상용 출시준비를 구별한다.

## 의사결정: 두 접근 비교

| 대안 | 속도·비용·품질·운영 위험 | 결정 |
|---|---|---|
| A. Sol Ultra가 기존 설계 대신 전체 제품을 재작성 | 초기 화면 품질·시각적 진척은 빠를 수 있으나 긴 설계의 예외 처리, API/DB 계약, 보안, 보존·복구, 납품조건 누락 위험. 소스 회귀·재개발/재테스트 비용 큼 | **선택하지 않음** |
| B. 기존 총괄이 소스/설계 정본 보유, Sol Ultra가 독립 감사·선택적 UI/UX 개선 | 요구사항 추적표 구축에 초기 비용 필요하나 기능 누락·데이터 훼손 위험 감소, 기존 테스트/설계와 비교 가능, 코드 최소 수정·PR 단위로 운영 | **기본 표준** |

## 역할·권한

- **GitHub 고정 정본:** 제품별 해당 repo/branch **확인된 최신 SHA**의 `HANDOFF.md → STATUS.md → AGENTS.md → REQUIREMENTS.md → 실제 최종설계(FINAL_BLUEPRINT.md, BLUEPRINT_100.md, FINAL_DESIGN.md, ACCEPTANCE_MATRIX.md 등 제품별 명칭) → 소스·테스트** 순서로 읽는다. 가장 최근 확정한 사용자 요구사항이 정본에 반영되었는지 확인. 문서 간 충돌·빠진 설계는 임의로 축소/추가하지 않고 `HOLD / OWNER_DECISION_REQUIRED`로 보고.
- **해총/담당 총괄:** 기능·트리거/이벤트·데이터 입력/저장·조인·API/비용·인증/보안·재시도·중복 실행·실패 복구·데이터 보존을 설계하고 원본 코드 최소 수정, 회귀/수용·고객 환경 검증, 사업자/게시·출고/권리 사용자 승인 관리.
- **Sol Ultra 독립 감사:** 전체 요구사항 식별자 `REQ-001…`를 **하나도 누락 없이** 추출한 `TRACEABILITY_MATRIX.md`를 만든다. 각 항목의 *설계 근거/원문 위치/구현 코드 경로/테스트 경로/재현 명령/실제 실행 SHA/결과(PASS, FAIL, PARTIAL, UNVERIFIED, NOT_APPLICABLE)/담당/차단 사유*를 기록. 표면 UI가 있다는 이유로 비동기 기능·복구·승인·고객 원본 보존을 PASS로 취급 금지.
- **Sol Ultra UX 개선:** 현행 UI/고객 워크플로를 스크린샷·실 브라우저로 확인한 뒤, 기존 API·DB 스키마·저장 데이터·프로그램 진입점·키보드·접근성·권한 체계를 유지하며 **별도 기능 브랜치/최소 diff/PR**로 디자인을 향상. UI/UX 변경과 핵심 기능 수정을 분리하여 검토. 리디자인 과정에 메뉴·옵션·필드·버튼·오류 상태·예외 경로가 사라지지 않는지 자동/수동 검사.
- **감사 분리:** (a) 기능·설계 누락 (b) 보안·데이터 손실/권한/오탐 (c) GUI/접근성/반응형/내비게이션 (d) 빌드·설치·업그레이드·고객지원/NOTICE 각각 독립 보고. 리뷰어가 자기 자신이 만든 개선 코드를 단독 최종 PASS 하지 않도록 총괄 회귀 검수.
- **가드레일:** 승인 없이 원본/고객 자료 외부 AI로 업로드 금지, 유료 API/토큰·환경변수·퍼블릭/프라이빗 설정·계정·권한·배포/결제·외부 수집 변경 금지. 기존 합법 원본/고객 자료는 보존, 위험 변경 전 백업·SHA와 명시적 승인. 회사 기밀을 Public 총괄 repo에 넣지 않는다.

## 제품별 95→100/판매 수용 7단계

1. **원본 동결:** 대상 GitHub repo·branch·HEAD 및 검증된 코드 SHA, 제품별 최종 100% 범위를 기록. 원본 복구 SHA 확보.
2. **요구사항 전수 목록:** 최종설계의 필수/선택 기능·예외·비기능(보안, 프라이버시, 데이터 수명, 성능, 설치, 로컬/오프라인, API 실패 복구 등)을 `REQ-* ID`로 분해. 기존 설계의 누락/애매성도 등록.
3. **정본 ↔ 코드 ↔ 테스트 ↔ 실제 실행** 4점 추적: 코드 파일 존재는 구현 주장일 뿐, 실제 PASS는 정확 SHA의 실행 로그·기대/실제 결과가 필요. `UNVERIFIED`·`SKIP`을 `PASS`로 바꾸지 않는다.
4. **Sol Ultra 독립 검토:** 상기 분리된 감사 보고서, 위험 등급 `BLOCKER / HIGH / MEDIUM / LOW`와 원본의 필수 기능 누락 및 UX 회귀 목록. 수정 대상만 별도 PR로 제한.
5. **담당 총괄 최소 수정:** 기존 구현을 최대한 보존하여 결함 수정. API 입력/출력·DB migration/업그레이드·실패 복구·클라우드 비용·권한·원본 무변경 회귀 테스트 추가.
6. **실행 검증:** Windows10/11·Mac/Linux(지원 명시 시), Chromium/Chrome/Edge(웹), 설치·업그레이드·재실행·미승인 네트워크·경로/인코딩·정전/파일 오류·백업/복원·SHA/ZIP/라이선스·데모 전과정을 제품 유형에 맞게 테스트; 브라우저/실기기 불가면 `미검증`으로 유지.
7. **출시 결정:** 모든 최종 필수 REQ 검증, 차단결함/데이터 손실/보안/라이선스 위험 해결, 고객 독립 셀프온보딩·문서·샘플·가격/실행 원가/지원·판매규정 점검, **소유자 승인** 후 판매/게시. 승인 전 `RELEASE HOLD`; 기술95 가정이나 AI의 단독 리뷰로 상용100 판정 금지.
