# 전 저장소 최종설계 기준 최종완성률 절대 규칙
> 사용자 직접 확정: 2026-11-13 KST · 정책 ID: OWNER-FINAL-BLUEPRINT-100 · 적용 범위: hibi89 소유 모든 프로젝트·해커톤·크몽 상품, 현재 및 이후 각 담당자·브랜치.
> 이 문서는 공통 **산정 절차**만 공개한다. 비공개 프로젝트의 상세 설계, 소스, 고객 데이터, 토큰은 공개하지 않는다.

## 1. 단 하나의 공식 분모
1. **최종완성률(%)의 유일한 기준은 사용자가 확정한 해당 제품의 최종설계도 전체를 100%로 하는 것이다.** 제출용 단기 범위, 해커톤 MVP, 시험 합격률, 소스코드 양, CI PASS 건수, 납품 포장 진행률 또는 담당 AI의 임의 목표치를 제품 최종완성률로 혼용하지 않는다.
2. 최종설계도와 이후 사용자 확정 변경의 우선순위를 명시한다. 설계 문서 이름(예: MASTER_BLUEPRINT/FINAL_BLUEPRINT/REQUIREMENTS), 경로, 기준 브랜치/SHA, 확정일을 기록하고 서로 모순되면 사용자가 최종 승인한 요구와 실제 구현 근거를 대조한다. **담당자 임의로 설계를 축소·삭제하거나 가중치를 조정하지 못한다.** 사용자 변경 승인이 있으면 이력과 이전 기준을 같이 보존한다.
3. 해커톤·샌드박스·합성 전용 단계는 반드시 `제한 범위 MVP 진척` 또는 `내부 엔지니어링 마일스톤`으로 별도 표기한다. 전체 설계에 없는 기능을 만들었다고 최종완성률에 가산하지 않는다.
4. 완성률 산정 전에 추적표를 만든다: `최종 요구 ID | 전체 설계 범위/수용조건 | 승인된 가중치 | 코드·제품 경로 | 실제 실행 검증 SHA/명령/결과 | 구현 상태 | 미검증·외부 의존성`.
5. 분모는 전체 요구의 승인된 가중치 합 100. **최종완성률 = 검증된 최종설계 항목의 승인 가중치 합 / 전체 설계 승인 가중치 합 ×100**. 항목을 일부 구현한 경우 사전 합의된 세부 수용조건으로만 부분 가점한다. **가중치가 미합의·항목 누락·근거가 불충분하면 수치 임의 생성 금지 → `최종설계 기준 재산정 대기(UNASSESSED)`**.
6. PASS는 정확한 SHA의 실제 실행에만, 작성된 테스트/모의 응답/신규 DOC는 구분한다. 기능·테스트·실 PC·브라우저·실 API·Production·고객·보안·권리·판매 승인을 서로 독립적으로 기록한다. 실제 실행 실패/미검증은 통과로 계산하지 않는다.
7. 최종 설계의 핵심 기능(예: 자연어→실 모델 해석→LA가 일반 워크플로 자동 설계·검증·실행) 부재 시 합성 CSV/SQLite 등 부분 MVP 성과만으로 85%·95%를 최종완성률이라 주장하지 않는다. 테스트 건수와 퍼센트를 비례 환산하지 않는다.
8. **기존 표의 85·95 등은 삭제/덮어쓰기 하지 않고 `과거 내부 마일스톤(산정기준 별도)`으로 보존**한다. 최종설계 기준 재산정 전에 이 숫자를 현행 공식 최종완성률, 제품 비교 평균 또는 상품 출시 가능 비율로 재사용 금지. 재산정된 공식 수치는 구 버전·산정표·SHA와 함께 교체 이력을 남긴다.
9. 사용자 지정 [작업중], [사용자 개입 필요], 상품 등록완료·목표·RELEASE HOLD 등의 별도 상태는 변동시키지 않는다. 목표 달성은 **최종설계 기준 산정과 수용조건 증거**로 재판정해야 하며, 임의 목표 변경·마커 해제 금지.
10. 제품 담당자는 업데이트할 때마다 제품 STATUS/HANDOFF→해총 `kmong-productization`의 현행 크몽 원장을 같은 작업 단위로 동기화한다. 브랜치·SHA·검증시점·산정표·FAIL/SKIP/미검증을 기록한다. 원격 반영 확인 전에는 `동기화 대기`. 자동 동기화가 구현된 것이 아니다.

## 2. 최종설계 기준의 예시: HAE / LA
- 사용자 확정 HAE: 자연어 요청→AI 모델(Qwen 등)이 의도·조건·데이터 흐름을 해석→타입·버전 있는 명령(IR)→LA가 노드/분기/실행 흐름 자동 설계·검증→오류/지원불가를 AI 계층과 왕복 교정→안전한 승인·dry-run·실행·재시도/복구·관측. SOVIA 위험/행동 감사와 DBVORA 업무 DB화/관리까지 **기존 전체 생태계 정본대로 필수**. 고객은 수동 노드·JSON 편집을 강요받지 않는다.
- HAE의 합성 CSV 패턴 5종/규칙 기반 플래너와 LA의 SQLite 결정론적 실행·복구 및 CI는 실제 기술 성과. 그러나 이것만으로 **자유로운 AI 기반 범용 워크플로 설계·수정이 완성된 것은 아니다.**
- 원래 내부 엔지니어링 `HAE 85%`, `LA 85%`는 과거 항목으로 보존하되, 최종설계 전체 기준 공식 퍼센트는 실제 요구 추적표와 사용자가 승인한 가중치·새 정확 SHA 검증 전까지 **재산정 대기**. `0% 완료`도, `85% 완료`도 아니다.

## 3. 시행 및 감사 기록
- 해총 크몽 브랜치를 공통 원장으로 하고, 전체 저장소 `AGENTS.md` 최상단에 본 정본 링크를 기록한다. 담당 작업 브랜치에 실제 반영된 경우에만 그 브랜치 적용 완료로 보고한다.
- 과거 공정률은 역사 자료로 유지. 새로운 퍼센트 확정 없이 임의 평균·순위 재산출 금지.
- 이 규칙의 문서 반영은 실제 새 기능 구현, CI 통과, 상용 배포 또는 전 저장소 완성률 100% 산정을 뜻하지 않는다. 비공개 상세 설계는 각 비공개 저장소에만 둔다.
