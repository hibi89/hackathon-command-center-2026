# 최종설계 전체 예상 공수 기반 진척률 — 아이디어 보관 (2026-11-15 KST)

> 상태: **IDEA ONLY / 시행 보류**. 사용자 지시: 결혼식 외출 전 아이디어만 중앙 해총 GitHub에 기록하고, 실제 산정·코드/원장 규칙 변경은 다음에 실시. 2026-11-13 승인된 [OWNER-FINAL-BLUEPRINT-100](FINAL_BLUEPRINT_COMPLETION_STANDARD_20261113.md)을 대체하거나 기존 공식 수치/가중치를 변경하지 않는다.

## 1. 관찰된 문제
- 완성률 70→85, 85→95, 95→100 각 구간의 실제 난이도·잔여 작업량·대기 시간이 들쭉날쭉하여 95% 후 남은 5%에 수십 시간 이상 소요될 수 있다.
- 기능 개수나 임의 5점·10점 할당은 구현/독립검증/실기기/보안/라이선스/고객 인수를 정확하게 예측하지 못한다.
- CI PASS·문서 작성·투입시간만으로 최종설계 작업 완료를 인정하지 않는 기존 원칙을 유지한다.

## 2. 다음 단계에서 비교할 3개 설계

| 방식 | 장점 | 문제 | 판단 |
|---|---|---|---|
| A. 요구사항 개수/담당자 임의 점수 | 간단 | 난이도·보안·검증 공수 왜곡 | 미래 공수예측에 부적합 |
| B. 실제 소모시간 / 초기 예상 전체시간 | 자동 계산 쉬움 | 실패·재시도·오류에 시간만 써도 100%에 접근 | **진척률 지표로 금지** |
| **C. 최종설계 세부 작업의 검증 완료 계획 공수 합 / 전체 승인 범위 계획 공수** | 잔여 작업량·중간 병목을 계량, 작업 실패에 가점 없음 | 초기 추정 오차와 범위 증가·의존성 관리 필요 | **향후 시험 운영 제안** |

## 3. 핵심 계산 정의 (향후 검토, 아직 공식 미적용)

- **최종설계 범위 기준선**: 사용자 확정 최종설계도 전체를 변경 불가 버전으로 고정. 필수 구현·통합·안전·복구·보안·라이선스/상업권·실기기·실서비스·실고객 인수 등 완료조건에 필요한 작업을 빠짐없이 나눈다.
- 작업 `i`에 계획 공수 `E_i`(인시 또는 모델 실행 공수 환산, 추정 범위/신뢰도 함께 기록)를 부여. **미검증 작업의 적립 공수는 0**. 부분가점은 작업을 먼저 객관적 수용 조건으로 세분화한 경우에만.
- **시험용 공수기준 진척률** `P_effort = 100 * SUM(E_i for acceptance_verified_i) / SUM(E_i for all mandatory_i)`. 예: 총 200h 계획 공수 중 150h 상당의 **검증 완료된** 작업이면 75%; 실제 투입 150h를 의미하지 않는다.
- **잔여 공수 전망** `R = SUM(remaining task current estimates) + rework reserve`; 범위(낙관/기준/비관)와 추정 시점을 공개. 완료된 계획 공수와 잔여 현재 예측이 달라 `P_effort`에서 달력시간을 역산하면 안 된다.
- **실제 경과시간/투입시간, 작업 공수, 임계경로 달력시간** 3개를 별도 기록한다. 병렬 개발·CI 대기·인증/고객/권리 승인 대기 등은 임계경로·차단조건으로 표시하며 단순히 인시 합을 달력시간이라고 주장하지 않는다.
- **작업 예상 공수 산정 규칙:** 난이도·의존성·오류재시도·테스트·통합·권리/보안·외부 인수 공수를 처음부터 포함. 불확실성이 큰 작업은 추정 구간 및 증거 신뢰도 기록. 근거가 없으면 수치 `UNESTIMATED`.
- **범위 관리:** 필수 요구 추가/삭제 또는 기준 시간 변경은 사용자 승인·이력(기존/신규 예상 시간·사유·SHA) 이후 별도 새 버전으로 반영. 재추정 전후 완성률이 자동 변할 수 있으므로 이전 분모·수치를 삭제하지 않는다. 출시 승인에 필요한 미검증 외부 게이트는 시간 가중치와 별도로 반드시 충족.
- **검증:** 각 완료 항목의 최종설계 ID, 수용조건, 근거 커밋 SHA, 명령·PASS/FAIL/SKIP, 실기기/브라우저/API/Production/고객/권리 범위, 검수자를 함께 기록.

## 4. 공식 완성률과 구분 — 특히 중요
- **현행 공식 최종설계 완성률**은 승인된 요구사항 가중치와 실제 검증 결과만 따른다(기존 `OWNER-FINAL-BLUEPRINT-100`). 공식 미산정 제품은 `UNASSESSED` 유지.
- 이번 아이디어는 **'예상 작업량 기반 시험용 진행률/잔여공수 예측'**을 추가하는 것으로, 70/85/95/100 기존 퍼센트 재계산·공식 점수/목표치·대기 표시·등록 이력 수정은 허용하지 않는다.
- 사용자 별도 명시 승인이 있어야 전제품 공통 분모·가중치 변경 또는 공수기준을 공식 완성률로 승격할 수 있다.
- `P_effort=100%`만으로 정식 제품 출시·크몽 상품 등록·보안 합격을 선언하지 않는다. 필수 수용 게이트 `ALL_PASS`, OWNER GO, 고객 권리가 별도 필요.

## 5. 나중에 진행할 검토 순서 (현재 작업하지 않음)
1. **작은 표본 시험:** FFAX/DBVORA/DATA2WEB/Astra PDF 등 확정 최종설계 + 전체 수용조건을 확인하고, 10~30개 작업으로 구분. 사용자의 기존 점수표/최종설계/원본 보존.
2. **독립 공수 추정:** 각 작업에 낙관/기준/비관 예상 인시·근거 및 검증 공수·외부대기 등을 할당; 미확인 수치는 `UNESTIMATED`; 공식 보고 전 전문가/사용자 확인.
3. **이중 보고 비교:** 기존 공식 가중치 방식과 시험용 공수 진척률, 잔여 예상 공수·임계경로, 실제 소요시간을 병행 기록해 예측 오차를 관찰.
4. **오차 보정/조건 승인:** 과거 완료 작업의 예상 대비 실제 기록으로 재추정 규칙 보정; 사용자 별도 승인 전 공식 분모/가중치/점수 변경 금지.
5. **정식 도입 조건:** 최종설계 누락 0, 필수 외부게이트 보존, 재산정 이력·SHA/검증 수준 재현성, 산정 왜곡/시간 뻥튀기 방어, 사용자 명시 승인.
