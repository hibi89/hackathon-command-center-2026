## 3. 최종 설계 100%, 코드 기능 100%, 판매 준비 100%, 크몽 게시를 구별

- `FUNCTIONAL_SCOPE_VERIFIED`: 최종설계 중 구현·기술 기능에 속하는 요구가 정확 SHA로 증명된 상태. **출고·판매 100%가 아님**.
- `INDEPENDENT_AUDIT_PASSED`: 독립 Codex 감사와 Sol 반박/보완이 끝나고 중대 결함이 없는 상태. 자가 진술이 아닌 재현 로그 필요.
- `DESIGN_ACCEPTED`: 선택한 디자인이 실제 UI/접근성/반응형/기능 보존 E2E를 통과하고 사용자 승인 상태.
- `COMMERCIAL_READY`: 고객형 패키지·Windows/브라우저·저작권·개인정보/보안·가격/환불·사후지원·실사용 수용 및 OWNER GO가 갖춰진 상태.
- `OFFICIAL_FINAL_100`: 사용자 확정 최종설계 전체의 승인된 고정 100점 가중치 중 **실제 완전 수용된 항목 합 100점**, exact SHA 증빙; 미검증/누락은 가산 금지. 필요한 고객/법률·영업 승인 포함.
- `KMONG_LISTING_DRAFT`/ `POSTED_VERIFIED`: 판매 상품 등록 초안 vs 실제 공개 게시·사용자 확인 URL·일자·이력. `OFFICIAL_FINAL_100`과 게시 여부는 별개 기록.
- 85·95%는 **과거 내부 엔지니어링 마일스톤**으로 보존. 승인 전체 100점 추적표 없으면 `UNASSESSED`; 과거 95%를 새 후보 상품 95% 또는 출시 GO로 자동 전파 금지.

## 5. 고객 권한과 자동 등록 제한

- 크몽 게시 자동화는 지원되는 **공식·허가된 연결 방법**이 있는 경우에만 실행. 실제 도구 연결/로그인/비밀번호·2FA/캡차 우회 불가 시 `DRAFT_READY / OWNER_ACTION_REQUIRED`로 남긴다.
- **가격·납품 범위·지원 기간·외부 공개·실 게시·결제/구독·새 계정/권한·민감 데이터 전송은 소유자 최종 승인 없이 실행 금지**. 기존 등록 이력과 중복 여부를 확인한 뒤 등록 초안을 만든다.
- AI 또는 다른 모델간 '합의'는 실제 실행 결과·고객 수용·법적 승인 대체 불가. 제3자 코드/폰트·모델·학습 데이터의 사용권/재판매 허가와 고객 정보 처리 근거가 불명확하면 `RELEASE HOLD`.
- AI는 사용자가 제공한 사전 동의 범위에서 코드/도구를 사용한다. 실제 가능한 도구가 없으면 해당 자동 실행을 **미검증/불가**로 표시하고 임의로 '등록완료'를 만들지 않는다.
