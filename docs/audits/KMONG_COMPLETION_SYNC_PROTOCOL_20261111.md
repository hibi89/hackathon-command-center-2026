# 크몽 최종완성률 동기화 운영 규칙 — 2026-11-11 KST

## 결론: 자동 동기화는 아직 없다
GitHub 저장소·브랜치 및 별도 ChatGPT 채팅 간에는 **실시간 상태 공유, commit-triggered webhook 또는 cross-repo 완성률 자동 집계가 구현되어 있지 않다.** 이 문서는 **담당 작업의 종료 게이트**를 정의한다. 문서 규칙만 추가해서 백그라운드 자동화가 생겼다고 주장하지 않는다.

## 모든 크몽 담당 작업의 필수 종료 체크리스트
1. 담당 제품의 최신 `HANDOFF.md → STATUS.md → AGENTS.md → REQUIREMENTS.md → 실제 소스`를 읽고 작업 브랜치와 승인/출시 조건을 확인한다.
2. 변경 및 새로 검증한 기능에 대한 **정확 코드/테스트 SHA**, PASS/FAIL/SKIP, 테스트 명령, OS, 실고객·Windows·브라우저·Production 미검증을 구분한다. 기존 제품 정상 기능·원본 보존. 단순 테스트 개수나 docs-only 커밋만으로 최종상품 %를 올리지 않는다.
3. 실제 기능 진척이 있으면 **최초 확정 100% 제품 범위** 대비 잠정 최종완성률을 재평가하고 수치 변화(+/- %p)와 이유를 제품 `STATUS.md` 및 `HANDOFF.md`의 최신 항목에 기록한다. 기능이 미검증/불변이면 숫자를 유지한다.
4. 해총 `hibi89/hackathon-command-center-2026@kmong-productization`의 [현행 16종 정본](KMONG_16_CURRENT_20261111.md)과 `KMONG_PRODUCTIZATION.md`의 **해당 행 및 전체 합계/평균·70% 미만 목록**, 중앙 `STATUS.md`·`HANDOFF.md`를 **같은 완료 단위**에서 동기화한다. 분모는 현재 활성 **16종**, Web REA Studio는 제외. 12개 저장소/18개 브랜치는 현재 조회 스냅샷이며 이후 변화 시 재조회.
5. 기록에 **repo/branch/원격 HEAD, 기능 소스 SHA와 docs SHA 구분, 검증 링크·범위, 미검증·RELEASE HOLD, KST 날짜**를 포함한다. 새 SHA는 GitHub에 실제 존재해야 한다.
6. Hub HEAD가 다른 담당자 때문에 바뀌면 **최신 HEAD 재조회→차이 병합→non-force 커밋**. 다른 담당자 문서·코드를 덮어쓰거나 force push 하지 않는다.
7. 제품 저장소까지는 업데이트했지만 허브 쓰기 권한/충돌 등으로 동기화를 못 한 경우에는 제품 `HANDOFF.md`에 **`KMONG_HUB_SYNC_PENDING`** 및 정확한 변경 숫자·소스 SHA·실패 근거를 남기고 사용자에게 미반영을 명시한다. 절대로 '해총 최신화 완료'라고 답하지 않는다.
8. 외부 고객 데이터·유료 API·권한/보안/원본·판매 승인·Production 변경은 사전 승인 필요. 판매 HOLD와 잠정 엔지니어링 진척 수치를 혼동하지 않는다.

## 작업 완료 보고 최소형
`상품 / 제품브랜치 / 기능 SHA / 검증 환경·PASS·FAIL·SKIP / 이전→신규 최종상품 % (근거) / 출시 HOLD / 해총 기록 경로·반영 커밋 SHA / 미검증`.

## 향후 진짜 자동화 옵션 (미구현)
- A 현재 방식: 각 담당 작업 완료 시 GitHub 커넥터로 같은 턴에서 중앙 동기화 (추가 인프라·비용 없음; **담당자 실행 의존**).
- B GitHub webhook 또는 주기 폴링으로 중앙 자동 집계: 비공개 다중 저장소의 읽기 권한·전용 토큰/앱 설치, 재평가 기준·동시성·비용/권한 승인이 필요. **현재 미설치/미승인**이며, 중앙이 자체적으로 완성률을 계산할 수 없는 주관적 품질 항목은 인간 검토가 필요.
